AI-generated image detection — full architecture

Hand-crafted forensic features + frozen pretrained extractors → unsupervised image clusters → random forest → calibrated probability. Built for the TikTok TechJam image-forensics track. This page is meant to be readable by someone who has never seen the project.

The one-paragraph version. A detector that decides whether an image is a real photograph or AI-generated. Instead of training a big neural network end-to-end (which tends to learn the quirks of the training set rather than the physics of fake images), every image is turned into a row of about 130 numbers that each measure something specific — how camera noise behaves, what the frequency spectrum looks like, how well a generator’s own decoder can reproduce the image, how “surprising” the pixels are to a compressor trained on real photos, and what the image is about. A random forest then combines those numbers, is calibrated so its output is an honest probability, and is analysed to show which measurements it relies on for which kinds of images.

Step-by-step, for a newcomer

1 · Data

Three public datasets provide labelled real/fake images. Because the archives are enormous (WildFake alone is ~1 TB of zips), images are never downloaded in bulk: the notebook fetches a batch of 400, computes all features, writes one small table to Google Drive and deletes the images before fetching the next batch. WildFake members are read directly out of the remote zip files with HTTP Range requests, so only the zip’s table of contents and the sampled images ever cross the network. One WildFake slice — COCO val2017 photos plus DALL·E 3 (“Advanced”) generations — is the organisers’ demo set; it is held out of training entirely and the notebook asserts this.

2 · Levelling

Real photos usually arrive as JPEGs and generator outputs as PNGs. A classifier would happily learn “JPEG artefacts ⇒ real” — a shortcut that has nothing to do with authenticity. Every image is therefore re-encoded once as JPEG quality 95 so both classes share the same compression history. Images are only ever cropped, never squashed to a fixed size, because resizing alters exactly the pixel statistics the forensic features measure (and fakes are often square while photos are not — another shortcut).

3 · Augmentation

Images on social platforms get re-compressed, blurred, resized and colour-shifted. Each training image yields two rows: an untouched copy and one copy with a single random transform from the organisers’ table (JPEG, blur, resize-then-upscale, noise, colour jitter, centre crop) at a random severity. The transform and its level are recorded in an aug column that is never a model input — it exists so that, afterwards, accuracy can be broken down by transform and severity to see which features survive which degradations.

4 · Views

Two views are built in memory from each (possibly transformed) image: a 256×256 crop at native resolution for the forensic features, and a 224×224 whole-scene view for CLIP.

5 · Feature extraction — the heart of the method

FamilyLearned parametersWhat it measures and why it separates real from fake
Physics trio (adapted multiLID)noneThree physical regularities of camera images. Anisotropy: real surfaces project to strongly oriented gradients (one eigenvalue of the local gradient covariance dominates); convolutional synthesis is more isotropic. Cross-scale consistency: for real structure the dominant orientation is the same whether you blur a little or a lot; multi-resolution generators break this. Noise–signal decoupling: sensor (shot) noise grows with brightness and is independent of edges; learned upsampling couples its residual noise to the content. Plus the correlation of noise between colour channels, a fingerprint of camera demosaicing.
FFTnoneThe radial power spectrum and a few scalars (slope, low/high-band energy share, peaks at ½, ¼, ⅛ of the Nyquist frequency). Upsampling layers leave periodic grids in the spectrum; low-frequency bands survive compression and blur, high ones do not.
CLIP ViT-L/14 (vision tower)≈ 304 M, frozenA semantic embedding of the whole scene — what the image is about and its style. Used three ways: 16 principal components as features; a linear probe whose output is a feature (trained cross-fitted: every training row only ever receives a prediction from a probe that did not see it, so the forest cannot learn a leaked score); and as the space in which images are clustered. Caveat surfaced during development: on a single source pair (OpenImages vs FLUX) CLIP alone separates the classes by content style, which is a dataset shortcut — the multi-source training set and the demo set are what keep it honest.
AEROBLADE≈ 266 M, frozen (3 VAEs ≈ 84 M each + VGG16 14.7 M)Latent-diffusion generators produce images through a decoder (a VAE). Push an image through such a VAE’s encoder and decoder: a generated image comes back almost unchanged, a real photo loses detail. The reconstruction distance (LPIPS total and VGG layer-2, pixel MSE, VGG-feature cosine) is computed for SD 1.5, SDXL and FLUX.1 VAEs, plus the minimum over the three.
ZED4.2 M (SReC) or 0.15 M (ZED-lite)A lossless image coder trained only on real photographs has a model of how real pixels behave. For each pixel it predicts a probability distribution; the actual coding cost (−log p of the true value) and the expected cost (the distribution’s entropy) are compared. Real images cost about what the coder expects; generated images are “cheaper than they should be”. The gap, averaged per resolution level, is the feature. The pretrained SReC coder (Open Images) is used; if it cannot be loaded, a small ZED-lite coder is trained on 2,000 reserved real images that never enter the forest’s data.

6 · Unsupervised clusters

Images are grouped into unnamed sub-types by k-means on their CLIP embedding (K chosen by silhouette score, each cluster at least 300 images, fitted on the training split only). The cluster id is fed to the forest one-hot, which lets it weight the features differently for, say, faces versus landscapes versus screenshots — and lets the analysis show which features matter for each sub-type. No human labels the clusters; a thumbnail grid is shown for inspection only.

7 · Splits

Train 70 % / calibration 15 % / test 15 %, stratified by dataset and label, and split by base image so a clean row and its augmented twin always land on the same side. The demo set is a fourth, untouched split.

8 · Model

A class-balanced random forest of 400 trees. Its hyper-parameters (tree depth, minimum leaf size, features per split) are chosen by an exhaustive grid search with group-aware cross-validation folds on ROC-AUC; the winner is refitted with an out-of-bag score. LightGBM is trained alongside purely as a reference line. Forest votes are not probabilities, so a one-feature logistic regression (Platt scaling) is fitted on the calibration split to map the forest’s log-odds to a calibrated p(AI); isotonic regression is drawn next to it for comparison.

9 · Evaluation and interpretation

ROC-AUC, accuracy, Brier score and expected calibration error on the test split and on the demo set, with reliability diagrams. The aug column gives accuracy by transform, severity, dataset, generator and cluster, including a cluster × transform heat-map on the demo set. Feature importance is computed by permutation (mean decrease in accuracy and in AUC), repeated for groups of correlated features (so collinear features do not dilute each other) and inside each cluster; the clean/augmented pairs give a “feature drift” table showing which features each transform destroys; SHAP values explain individual decisions.

10 · Deployment

Everything needed to score a new image is exported to one folder. aigc_inference.py rebuilds the whole pipeline from it (its feature code is copied verbatim from the notebook, so numbers match exactly); classify_folder.py scores a folder to JSON; dashboard.py is a Streamlit app where you upload an image, optionally apply the training transforms, and get a verdict with probability and SHAP contributions.

Glossary

ROC-AUCProbability that a random fake scores higher than a random real; 0.5 = coin flip, 1.0 = perfect ranking.
Calibration / Platt scalingMaking “p = 0.8” mean “80 % of such images are fake”. Platt fits a logistic curve on a held-out split; ECE and the Brier score measure how far predictions are from that ideal.
Cross-fittingTraining a sub-model in folds so that every training row gets a prediction from a model that never saw it. Prevents the downstream forest from learning an over-confident, leaked feature.
Group splitSplitting by base image, not by row, so an augmented copy can never be in the test set while its clean twin is in training.
Permutation importanceShuffle one feature’s values and measure how much accuracy drops. Features the forest actually uses hurt when shuffled.
SHAPPer-image attribution: how much each feature pushed this prediction towards “AI” or “real”.
Dataset shortcutA cue that separates the classes in the training data but has nothing to do with authenticity (file format, image size, prompt-like content). Levelling, cropping, multi-source data and the held-out demo set are the defences.
